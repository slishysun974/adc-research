# Gu 基线代码的信息边界核查（第一轮）

> 2026-09-17。核查范围：浮点／定点两级校准核心，EXP-009--013 的真值与训练数据流。这里的“在线”指校准算法在运行时可取得的信息；“离线”指研究者用来建立模拟测试电路和事后评分的信息。**没有据此确认 Gu 芯片内部实际总线。**

## 先说结论

旧 EXP-010/011/013 的校准配置由 `build_two_stage_oracle(pipeline, nonidealities)` 建立。它读取了合成模拟 PWL 曲线的边界，计算理想逆函数系数。虽然这些实验随后把系数初始化为 1，并没有把 oracle 斜率直接当作更新目标，但分段宽度、段数和步长归一化是沿着 oracle 对象传入的。因此旧实验**不能证明在线算法完全不依赖已知模拟曲线**。当前测试曲线的等宽边界恰好给出架构数字位宽预设的 128／32 码分段；这只是本例数值相同，不是“真实增益已知”。

本轮已将这些在线配置改为从架构的 `pwl_implications` 和数字重构权重生成单位系数基线。完整平台轨迹先缩成五个数字字段，浮点／定点更新函数现在只接收该数字样本。oracle 移到 `src/adc_research/evaluation/` 作离线参考；旧 `calibration/known_truth.py` 保留兼容导入。其余历史 oracle 演示不改写为未知曲线实验。

## 查到了什么

|---|---|---|
| `calibration/gated_lms.py`、`fixed_gated_lms.py` | 更新只用 dither、校正后输出、当前系数与固定参数；未发现直接读真值 | 保留，新增无 oracle 导入检查 |
| EXP-010、011、013 | 用模拟真值生成的 oracle 对象给在线校准提供分段几何；oracle 斜率另用于评分 | 几何来自架构位宽；oracle 只用于事后系数误差、理想上界和验收指标 |

## 尚未解决，不能掩盖

1. EXP-011 的 `initial_coefficients` 从 EXP-010 同一合成曲线训练的结果抄入。它可以研究此曲线附近的稳态波动，**不能**代表换一条未知曲线后的冷启动速度。EXP-011 的“到达 oracle 系数误差阈值所需样本数”也是离线评价量，芯片不能凭它判断何时停止更新。
2. EXP-010 和 EXP-013 对同一合成曲线的固定码中心反复训练，随后仍用相同曲线／码中心评分。这里尚无独立模拟曲线或输入分布的留出测试，也未证明对未知曲线的 SNDR／SFDR 改善。
3. 数字样本字段只是当前**候选架构**认为可见的量。需从论文与真实设计核对各级原始码、dither 标记的保存方式、主辅路径时序及位宽。完整平台轨迹的旧兼容校正接口仍存在，不能拿它直接实现新的在线训练。
4. Gu 数字 PWL 分段宽度来自架构位宽，不要求模拟曲线分段；但若模拟误差不能用这组数字基函数表示，oracle PWL 也不是“真实最佳系数”。新阶段二仍须研究不可表示误差和信息不足的反例。
5. EXP-012 的 oracle 定点校正测试不是定点在线学习；EXP-013 是当前定点更新候选，尚未有 Verilog、综合面积／时序／功耗或随机输入下的留出验证。

## 证据和下一个验证门

新增测试验证：128／32 码分段能只由架构数字位宽推出；旧合成曲线 oracle 的分段宽度相同、斜率不同；只改模拟残余和平台物理标记而不改五个数字字段，在线更新的系数及输出不变；完整平台轨迹不能传入在线校正接口。全部回归测试通过并不代表外部曲线的性能已验证。

完整重跑 EXP-010（`artifacts/runs/EXP_010/online_boundary_audit_20260918/`）已通过其原验收条件；在这条**相同合成曲线**上，最终系数及平均绝对码误差 0.3363344277 与既有记录一致。这只验证拆分没有改变该例的数值行为，不是跨曲线泛化证据。

下一步先建立另一条**不按数字分段对齐**的模拟测试曲线，以及完全未见过的输入条件；固定在线配置和步长，不按留出数据重新选参数。比较 Gu 冷启动、稳态频谱和失败概率。再核实真实可见总线，最后才谈 RTL 资源成本与新算法优势。

> 后续进展（2026-10-01）：[EXP-021](../../reports/experiments/EXP_021_GU_CROSS_CURVE_COLD_START_V1.md) 已用两条平滑三次模拟曲线、固定在线步长和独立输入记录完成冷启动留出。它报告了固定 64 轮终点的频谱，并发现一条曲线的验证误差先降后升；**稳态和失败概率尚未确定**。实际芯片可见总线、PRNG/抽取时序及定点 RTL 仍待核实。
