## 1. 问题与验收目标

本轮服务阶段三的可实现Gu基线。既有证据是指定数字合同下功能回放通过，而100 MHz综合估计失败：WNS −50.309 ns，最长路径约60.847 ns，经过后级PWL、前级重建／PWL及前级更新。先前映射和缩位宽尝试仍失败，见[原报告](CIRCUIT_REVIEW_VIVADO_RESULTS_2026-10-11.md)。

需要解决的是长组合反馈与时钟周期的冲突，同时保持同一笔转换使用旧状态、两级同时提交的规则。验收同时要求：接受的数字序列与原参考逐转换一致；控制及IO仍受100 MHz约束；实际布局布线的建立／保持检查通过；布线网表在实际延迟下完成回放。科学主线的学习机制、未来留出及模拟模型不扩展。

## 2. 实现与接口

[多拍核心](../../rtl/gu_baseline/two_stage_multicycle_candidate_a.sv)锁存输入，登记校正结果，再用八个并行逐位除法器计算原整数请求。状态更新复用[精确bank](../../rtl/gu_baseline/fixed_gated_lms_exact_candidate_a.sv)；`EXTERNAL_COMMIT`使组合计算与最终写回分离，`EXTERNAL_DELTA`使用外部整数请求。两参数均默认0；原[逐转换顶层](../../rtl/gu_baseline/two_stage_adaptive_exact_candidate_a.sv)将提交端接常数1、外部请求端接0，保持原方式。

| 时刻／信号 | 合同 |
|---|---|
| 接收沿E0 | `!reset && ready_in && valid_in`时锁存五字段数字输入 |
| E1—E15 | 保持样本和八状态，持续计算；忙碌输入不被接收 |
| E16 | 登记旧状态算出的码、有效、门及学习量，共53位中间值；八状态仍保持 |
| E17 | 登记八个原带偏置分子及符号，清零商和余数 |
| E18—E38 | 每沿处理一位分子，完成21步整数除125 |
| E39 | 由登记值公布最终码／诊断量，同时写回两级八状态；完成脉冲拉高 |
| E40 | 最早接收下一样本；完成／有效脉冲恢复低 |
| 无效样本 | 仍完成事务，`valid_out=0`，码／门／学习量为0，八状态保持 |
| 核心复位 | 同步高有效，取消事务、恢复单位状态；释放后一个沿拉高就绪 |
| FPGA评估顶层复位 | 另受时钟锁定同步约束，调用方等待就绪 |

输出不带反压，调用方在`done_out`脉冲读取完成状态，只有`valid_out=1`时最终码有效。非完成周期最终码可保持旧值。接口的等价对象是**已握手接收的序列**，不是未经握手的每拍输入流。

设一次接收前状态为A、样本为x。锁存后至E39前无状态写回，两级校正和门始终取原F(x,A)。E16登记这些旧状态结果，原整数请求在随后21步精确求得；E39同时公布旧状态输出并写入U(A,F(x,A))，下一次接收在该沿之后。这与原逐转换递推逐次对应。无效及禁用坐标送0请求，bank写回相同状态值；复位恢复单位状态。该结构推理与有限回放共同支持接口等价，未执行全输入形式验证。

逐位除法从余数0出发，每步将7位余数与下一个分子位拼成8位数，若至少125则减125并追加商位1，否则追加0。由于输入余数小于125，新数至多249，一次减法后仍在0—124；归纳得到21步后的商为原21位带偏置分子除以125的下取整。保留低14位与旧函数的14位赋值一致，然后恢复原符号、门及Q22饱和。带偏置分子的位宽、符号处理及加62均与旧函数相同；原算术回归继续覆盖共用的饱和加法。

提交脉冲只控制寄存器写回，不能在最后一拍才启用PWL或门运算。后者会从控制信号重新启动整个长算术链，不能享受16拍计算时间。

## 3. 时钟与约束为什么有效

[FPGA评估顶层](../../rtl/gu_baseline/vivado_review/multicycle_cost_top.sv)使用输入缓冲、MMCM和两个全局时钟缓冲。MMCM为10倍再除10，VCO为1 GHz，工作时钟为100 MHz；通过全局反馈补偿时钟网络偏差。未用输出也显式除10，避免默认1 GHz输出违反器件模型的最小周期。锁定信号经两级同步后释放核心复位。依据见[AMD器件原语说明](https://docs.amd.com/r/2022.1-English/ug953-vivado-7series-libraries/MMCME2_BASE)。

约束保留10 ns时钟、输入／输出min 0.2 ns与max 1 ns、输出负载1 pF，IO为LVCMOS33、FAST、12 mA。最终码／有效／完成的14个寄存器放入IOB；就绪寄存器还有内部扇出，保留在逻辑区。没有用户板卡引脚约定，不生成可上板bitstream。

建立16周期、保持15周期的例外，只从18位锁存样本及184位状态，指向E16的53位中间寄存器。脚本对三组数量断言，选择为空或变化即失败。53位中间寄存器保留明确边界；样本从E0稳定到E16，八状态直到E39才写回，因此例外有实际使能合同。分子登记、逐位除法、状态写回、最终输出、计数、提交、就绪、完成、复位及外部IO均保持单周期。没有整时钟域放宽、false path或未约束数据端点。建立／保持成对设置依据为[AMD UG903](https://www.xilinx.com/support/documents/sw_manuals/xilinx2022_1/ug903-vivado-using-constraints.pdf)。

## 6. 结论与保留边界

本轮判别目标是：允许降低接收速率后，能否保留原逐转换结果并建立满足100 MHz的具体实现。**原递推的RTL功能、同布线DCP的完整功能核对和Zynq 100 MHz建立／保持时序已有支持，代价是40周期接收、2.5 MS/s；完整SDF验收仍失败。** 单原语回放与整网表的区别要求继续核对延迟仿真上下文，不能据当前码差直接改变Gu算术，也不能以功能／STA或原语PASS替代完整SDF。

原2022.1执行环境已恢复，入口Bash语法检查与同合同失败校准已实际完成；下一必要条件是取得受支持的独立模拟器或另一XSim版本，再核对原语与第34行。候选短核对正负控制均通过后才进入完整回放。当前缺少该独立环境，没有新判别依据前停止追加脉冲选项扫描、延长计算拍数或重新映射。当前未发现官方已确认的对应缺陷，不称工具bug已证实。若需安装／取得其他工具，先明确工具条件和最短核对合同，不重跑科学数据或原训练矩阵。

本次续查未改算术RTL、网表、DCP或原SDF，没有新增综合／布线、ADC源转换、训练、评分、FFT、留出、NG／EXP或算法；只复用旧输入与已有功能／STA证据做有限仿真诊断，补正复现配置和日志验收。多拍实现不证明每拍吞吐100 MS/s、原Artix-7已通过、Gu芯片的3 GS/s能力、定点闭环频谱或ASIC面积功耗。原科学主线、既有统计结论、未来6007／8009边界及旧失败均保留。

当前v10额外守住已冻结的逐转换旧状态递推与两级同时提交，采用40周期一事务。论文没有要求这种项目调度。按原文功能边界把校正与后台提取分开，有理由研究是否能在保持明确候选更新合同下改善吞吐和资源；这仍是待验收的架构方向，尚未实现，也不保证FPGA达到论文ASIC速率。改变抽取、更新频率或系数生效时间会改变原逐转换状态轨迹，须另定义候选参考，不能继续声称逐转换完全等价。原文并未公开可直接替换项目除125、Q22隐藏精度、门等值、舍入／饱和及广播的完整位级规则；不能为了方便移位而擅自替换当前学习率并称为论文复原。

这些结构依据能够指导架构研究，尚不能直接修复本次相同CARRY4模型、稳定输入下的SDF输出差异。新架构即使避开某种映射并通过，也须作为新实现重新验证，不倒推旧网表已经通过。本轮只形成上述来源对照与适用范围，没有改RTL、学习率、更新合同或验收门槛；原SDF问题继续单列。


针对工程实现还有可在现有工具继续的结构性研究路径：保持已握手数字序列、原定点算术和系数递推，按单级PWL、两级重构及更新模块边界设计寄存器与同步预计算，再对新旧结果作逐位等价和同约束实现／SDF核对。该路径可检验新实现能否通过，不承担解释旧延迟仿真异常的任务；提出该方向时尚未冻结新候选，其后按用户继续指示完成的实际实现与局限见第8节。若采用不同抽取／更新合同，则按前述边界另行定义，不能用原逐转换验收替代。

|---|---|
| E0 | 锁存样本及八个旧Q1.10系数快照 |
| E1—E4 | 后级PWL：段／系数／前缀选择、乘法与偏移、舍入求和、符号恢复 |
