# 模块三：Gu算法实现、定点与硬件基线

> 编写：2026-10-16；证据截至2026-10-15。依据用户确认的[七模块分类](PROJECT_STRUCTURE_AND_RESEARCH_REVIEW_2026-10-16.md)。
> 本文主体综合既有实现和验收记录；2026-10-16另按用户要求开展多拍时序整改，最新工程验收见[专门报告](RTL_MULTICYCLE_TIMING_2026-10-16.md)。下文旧资源／时序数值保留原运行身份。

项目已建立Gu校准的软件、定点和可综合RTL候选，并完成相应有限功能核对。原逐转换Artix-7基线未通过100 MHz；新增多拍Zynq候选继续整改，当前串行除法版接收间隔40周期，100 MHz完整验收见专门报告。**硬件结论必须同时注明时钟与接收速率；目标工艺面积和功耗仍未完成。**

## 1. 要实现的算法是什么

Gu用分段线性函数校正内部数字码。每段使用斜率系数，段间偏移由前面各段累计得到，使校正函数连续。两级候选共有八个斜率系数；处理时先校正后级，再重构前级局部数字量，完成前级校正和扰动扣除。

后台学习使用dither，即注入且已知的小扰动。算法观察校正输出是否仍与扰动正负相关，再调整系数。第一系数使用所有学习样本，后续系数按输出幅度超过相应下限的条件更新，这就是门控。后续门不是只接受本段幅度的上下限区间。

公开原理不等于完整芯片实现。实际四段步长、内部累加位宽、抽取统计和广播时序未充分公开。本项目把这些补足为明确候选，逐项验收，不把程序可运行当作来源已经确认。

## 2. 从浮点到定点，解决了什么

EXP-009、010建立门控更新与两级浮点集成。随后EXP-012、013把校正器使用的系数精度与内部更新精度分开。

| 数值位置 | 本项目主要候选 | 实际作用 |
|---|---|---|
| 校正数据 | 保留3个二进制小数位，记为Q3 | 规定乘积、偏移和门判断的分辨率 |
| 对外使用的系数 | 保留10个小数位，记为Q1.10 | 最小系数步进为1/1024 |
| 内部学习状态 | 保留22个小数位，记为Q22 | 先累积小更新，再导出校正系数 |

为什么需要两种系数精度？一次更新可能小于1/1024。如果每次都直接取到接口精度，小变化会反复消失，无法累积。EXP-013的10小数位累加器组中，全部有效门控更新都被舍入成零；提高内部精度后才能保存它们。

反过来，接口系数没有改变，也不能断言算法完全停止：内部Q22可能已变化，只是尚未跨过导出边界。这个区别后来成为判断停更、状态承接和恢复行为的重要条件。具体舍入、饱和和中间总位宽是项目候选规则，不能从论文接口位宽直接推断。

## 3. 硬件核对走到了哪里

EXP-030先核对单级定点校正，EXP-031连接冻结系数的两级输出，EXP-032加入逐转换在线学习。验证比较最终码，也检查门、更新量和八个隐藏状态。EXP-034提供通用综合基准，EXP-035进一步把固定步长更新写成精确等价的整数算术，减少不必要的宽算术开销。

这些结果支持指定输入和规则下的软件／RTL功能一致性。RTL是描述数字逻辑的代码；可综合表示工具能把它映成逻辑结构，不表示该结构已经达到目标速度。

后续Vivado展示工程把候选映射到Artix-7 FPGA。原基线使用2548个查找表、184个触发器和4个DSP运算块。10 ns时钟，即100 MHz目标下，最差建立时间余量为−50.309 ns，时序未满足。后续两组映射／位宽尝试有资源或路径改善，但仍未通过同一时序目标。

最长路径涉及后级校正、前级数字量重建及前级更新。若通过插入寄存器缩短组合路径，就会改变观测和系数生效的对齐关系，需要重新规定学习时序；不能将它当成无行为影响的机械修改。

## 4. 三种实现结果需要分开

**浮点演示性能**来自明确的人工模拟曲线和学习规则。它说明该行为模型可以出现校准收益。

**定点与RTL功能核对**说明指定候选按约定进行计算。现有主要RTL逐转换更新，后期学习研究多采用每120次转换冻结、末尾提交的窗口规则，两者不能直接共用性能结论。

**综合资源与时序**描述具体工具、器件和约束下的实现。FPGA资源不能换算为ASIC面积、模拟ADC功耗或3 GS/s实现能力。原展示基线没有完成布局布线；本轮多拍Zynq独立完成布线，完整验收见专门报告。板级验证及定点网表闭环频谱仍未完成。

旧电路汇报中的两份本地验收JSON当前缺失，相关后续交付核对不能凭这两份记录复算。原报告保留了这一可得性限制；本轮写作不补造记录，也不将旧结论升级为重新验收通过。

## 5. 对整体课题的意义

这一模块把算法讨论落到了可检查的数值和状态规则上。它说明小步长能否保留下来、更新何时生效以及计算链有多长，都是算法的一部分。

后续比较新算法时，应使用同样清楚的输入接口、更新时序、位宽、吞吐和时钟边界，再比较输出收益与成本。现有基线为这种比较提供起点，尚不构成新算法更省或更快的证明。
