# EXP-034：Gu 数字候选的首个通用逻辑综合基准

> 2026-10-04。正式摘要：`artifacts/runs/EXP_034/generic_staged_v1/summary.json`。对象是 EXP-031/032 的研究候选，不是 Gu 芯片的实际 RTL。

当前逐转换在线候选可以映为通用逻辑网表，并在已有数字压力记录上保持最终码一致。加入在线更新后，本次映射的逻辑规模和最长组合路径明显增加。这给出了值得检查的实现成本线索；没有工艺映射，不能推断面积、频率、功耗或真实 Gu 硬件的瓶颈。

## 冻结的比较边界

[两个综合顶层](../../../experiments/exp_034_generic_synthesis/cost_tops.sv)都只导出有效标记和最终 12 位码。去掉诊断输出，可避免为了观察内部量而额外保留逻辑。已有校正及 LMS RTL 源码没有修改。

| 项目 | 冻结系数链 | 在线更新链 |
|---|---|---|
| 数值依据 | EXP-031 | EXP-032 |
| 数据／系数 | Q3／无符号 Q1.10 | 同左 |
| 系数来源 | 八个 11 位外部输入 | 八个 23 位 Q22 状态 |
| 更新时序 | 无内部更新 | 本次旧系数评分，上升沿同时更新，下次生效 |
| 输入／输出位数 | 107／13 | 21／13，输入含时钟和同步复位 |
| 系数存储计入范围 | 不计，需在系统比较时另补 | 计入 |
| 四路抽取、广播及 flash 适配器 | 不包含 | 不包含 |

冻结链的“冻结”指评分时系数由外部提供，综合时没有绑成常数。因此两条链都保留可变系数校正逻辑。不过，两者系数存储边界不同，不能把下面的差值直接解释为 LMS 算术单独占用多少面积。

## 工具与映射

在 `D:\ADC\artifacts\tooling` 内安装 YoWASP Yosys `0.69.0.0.post1233`，实际版本为 `Yosys 0.69, git 9f75ca1f9`。依赖版本、RTL SHA-256、生成脚本、粗综合网表、最终网表及日志均随运行产物保存。[重现入口](../../../experiments/exp_034_generic_synthesis/README.md)列出命令。

采用 `-flatten -noabc -noalumacc`，粗综合之后分 12 步映射并做常数与公共逻辑消除，再运行 `techmap -assert`、`check -assert` 和单元类型检查。两条链使用同一流程。没有工艺库、时钟约束、吞吐约束或延迟模型。Yosys 的 `stat` 可报告单元数；面积计算需要另外提供库，见[工具统计定义](https://testyosys.readthedocs.io/en/latest/cmd/stat.html)。本次使用的命令语义也已由安装版本的 `help synth/stat/techmap/ltp` 核对。

先前直接调用常规映射时，在线链在展开大量中间逻辑后抛出 Wasm 异常，未得到最终网表；日志没有充分确定异常根因。这次分步映射成功，改变的是综合处理顺序，没有缩减 RTL 位宽或更换算术。直接尝试保留在 `artifacts/runs/EXP_034/generic_v1/`，不作为本表的正式结果。

## 结构结果

| 指标 | 冻结系数链 | 在线更新链 |
|---|---:|---:|
| 通用逻辑单元总数 | 4,799 | 200,629 |
| 组合单元数 | 4,799 | 200,445 |
| 状态位数 | 0 | 184 |
| AND／OR／XOR | 2,096／842／1,252 | 77,024／45,240／28,269 |
| NOT／MUX | 161／448 | 23,923／25,989 |
| 最长组合拓扑路径单元数 | 193 | 1,178 |

这里的“路径长度”仅是串接逻辑单元个数。没有各单元延迟、布线和负载，不能据此计算最高时钟频率。通用单元也不是等面积的门，不把总数换算为等效 NAND 面积。

在线链粗综合网表保留八个 `$div` 和八个 `$mod`，被除数和结果各 64 位；第一级除数为 `4000`，第二级为 `250`。该结果对应目前幅值除法、取余和最近偶数舍入的直接实现。它与较大的映射规模一起，提示后续应先审计宽整数更新实现。还没有逐运算消融或工艺报告，不能声称这些运算已被证明是唯一或主导面积来源，更不能把当前候选的实现代价推广到论文芯片。

## 最终码回放

完整网表记录在 Windows 本地验证：用已有 GCC 15.2.0 编译[小型通用单元回放器](../../../experiments/exp_034_generic_synthesis/replay_gates.c)，从 Yosys JSON 读取拓扑有序的组合单元和同步触发器，并与既有 Python 数字记录比较。触发器复位优先及使能规则核对了安装包的 `share/simcells.v`。用户确认恢复 WSL 授权后，又使用 `Ubuntu-20.04-D` 内已有 Icarus 10.3 检查 HDL；范围另列于下文。

回放逐位传播 `0/1/unknown`，不会把未知值强行置零；两级状态在同一沿同时写入。它模拟每次输入稳定后的逻辑值，不模拟毛刺、延迟或建立／保持时间，也不能替代完整 HDL 仿真器。

| 检查 | 结果 |
|---|---|
| 冻结链 EXP-031 记录 | 18,432 条，全部 13 位输出一致 |
| 在线链 EXP-032 连续记录 | 8,263 条，全部 13 位输出一致 |
| 在线链再次复位后重放前缀 | 128 条，全部一致 |
| 每次在线记录前插入空闲时钟 | 共 8,391 次，空闲输出为无效／零，随后参考轨迹仍匹配 |
| 原在线记录的 1,048 条无效观测 | 保留在连续回放中，后续输出仍匹配 |
| 故意翻转第一条参考的最终码 bit | 两条链均报不匹配，负向检查通过 |
| 回放器单元逻辑、未知值及同步状态自检 | 通过 |
| 项目 Python 测试 | 178 项通过 |

这些是有限记录的最终码核对。本次没有导出综合网表的八个累加器轨迹；原 RTL 的逐次累加器核对仍见 EXP-032。全输入形式等价证明也未完成：一项内部节点 SAT 检查耗时后被停止，不能仅凭已通过的输出局部检查宣称全网表已证明等价。

WSL 已完成冻结链 RTL 与原 Verilog 网表各 18432 条、在线 RTL 连续 8263 条及复位后 128 条的 HDL 检查。在线原 Verilog 网表运行未完成；隐藏内部别名、清除无用内部线并以原语实例导出的版本也在 120 秒内未进入可观察检查进度。清理后仍有 200629 个单元和 184 位状态，完整本地回放通过，但这不能代替该版本的 HDL 成功结果。

[逐位导出器](../../../experiments/exp_034_generic_synthesis/export_scalar.py)另将原 JSON 的每个单元和引脚写成标量 Verilog，保留原单元、连接、端口和触发器规则，不改算术。该版本在约 3 秒内进入调度。前 16 条记录及复位后再放前 16 条全部通过，另检查 32 次空闲时钟和两级非法字。正式运行约 194 秒，记录 `678545190` 个 `other events`；此事件数来自 HDL 仿真器，不是硬件开关活动或功耗。

## 主线判断

阶段三已经从“只有功能 RTL”推进到“有可复算通用逻辑网表及数字回放”。同日完成[固定 dither 合同下的精确更新关系及范围](../../stages/03_gu_baseline/CANDIDATE_A_EXACT_UPDATE_ARITHMETIC_V1.md)，173872 组允许整数检查一致。本实验建立时尚无改进 RTL；后续 [EXP-035](EXP_035_EXACT_UPDATE_RTL_V1.md)已保持 Q22、步长、舍入、饱和和生效顺序，实现专用整数更新，同流程在线单元由 200629 降为 21121，并完成连续码／状态及完整有限 HDL 网表核对。EXP-034 的原实现和历史结果保持不变，不能以任意缩位的低单元数代替功能验证。

真实逐位总线、四路抽取聚合、系数广播、主辅动态和物理覆盖资料仍是更高优先级的外部证据。取得目标工艺库、器件及约束后，才能建立面积、时序和功耗基准。本实验没有改变阶段二的芯片性能证据边界，也没有进入新算法比较。
