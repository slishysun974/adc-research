# 项目阅读指南与文档索引

这里是统一阅读入口。首次了解课题，先沿研究问题建立认识；准备接续工作，再核对当前证据和执行边界。两种阅读目的使用下方不同路径。

## 首次阅读：了解课题与已有成果

本项目以Gu为基线，研究内部数字信息、系数学习与最终误差之间的关系，再据此寻找可实现的改善。论文中的数字校正函数、项目选用的模拟测试曲线，以及离线评分目标，需要分别理解。

如果已经读过Gu论文，建议按下列顺序阅读。先看问题、方法、结果和条件，末尾证据表可在第二遍再查。七模块是分类，不要求按一至七顺读；四阶段是推进路线，不以模块数量衡量完成度。

| 顺序 | 阅读内容 | 应当建立的认识 |
|---|---|---|
| 1 | [章程](PROJECT_CHARTER.md)的“一句话目标”“必须守住的边界”和四阶段 | 项目目标、在线信息边界及尚未完成的阶段 |
| 2 | [Gu评价第4节的对应关系表](reports/GU_ALGORITHM_EVALUATION_V1.md#4-本项目实现与gu原文的对应关系)；第一次可跳过4.1详细合同 | 哪些来自原文，哪些是项目候选约定 |
| 3 | [模块六：后台性能、稳定性与适用条件](reports/RESEARCH_MODULE_06_BACKGROUND_PERFORMANCE_V1.md) | 持续学习产生哪些现象，收益、启动和恢复为何分别评价 |
| 4 | [模块五：激励、抽样与参数更新](reports/RESEARCH_MODULE_05_LEARNING_V1.md) | 平均方向、持续变化和量化位置差怎样影响学习 |
| 5 | [模块七：剩余误差来源与改善空间](reports/RESEARCH_MODULE_07_ERROR_MECHANISMS_V1.md) | 哪些原因已有受控证据，较好表示与在线取得之间还缺什么 |
| 6 | [模块四：数字观测与校正目标](reports/RESEARCH_MODULE_04_INFORMATION_V1.md) | 观测、表示、学习目标和在线能力分别能证明到哪里 |

时间有限时，先读第1、2、3、5项，形成全貌，再补第4、6项。若尚不熟悉Gu原理，可先看[Gu评价第2—3节](reports/GU_ALGORITHM_EVALUATION_V1.md#2-gu算法解决什么问题)。

按兴趣补充另外三个模块：

| 想进一步了解 | 阅读入口 |
|---|---|
| 实验信号链是否可信、主辅路径怎样表达 | [模块一：实验平台](reports/RESEARCH_MODULE_01_PLATFORM_V1.md)，需要看信号时再进入[Simulink模型](../simulink_adc/README.md) |
| 码边界、静态指标和频谱怎样推导 | [模块二：信号链预测](reports/RESEARCH_MODULE_02_PREDICTION_V1.md)；理解方法后再读理论框架和原推导 |
| 定点、RTL功能、资源和时序 | [模块三：Gu实现与硬件](reports/RESEARCH_MODULE_03_IMPLEMENTATION_V1.md) |

阅读后应能说明：在线算法实际看见什么；为何更多样本或更小步长未必同时改善所有指标；为何离线较好系数不等于在线算法已能取得。模块汇报综合截至2026-10-15的证据，当前准确进度由STATUS维护。

## 从结论追溯证据

首次阅读无需通读全部EXP、NG、决策或历史。选一个关心的判断，从模块末尾证据表向下查：

- 学习率与幅度切换：模块六 → [EXP-069](reports/experiments/EXP_069_GU_LEARNING_RATE_V1.md)／[EXP-070](reports/experiments/EXP_070_GU_LEARNING_RATE_SWITCH_V1.md)。
- 采用样本范围与门来源：模块七 → [EXP-075](reports/experiments/EXP_075_FRONT_SAMPLING_INTERVENTION_V1.md)／[EXP-076](reports/experiments/EXP_076_FIXED_MEAN_GATE_INTERVENTION_V1.md)／[EXP-077](reports/experiments/EXP_077_INITIAL_GATE_INTERVENTION_V1.md)。
- 信息和学习目标：模块四 → 原理论的定义、条件、证明或反例，再按需查看数值核对。

先确认比较对象、评价指标和成立条件，再读证明、代码与原始记录。数学结果、同模型双实现一致、有限输出收益和芯片物理证据分别判断。完整分类与全部实验归属见[七模块汇报入口](reports/PROJECT_STRUCTURE_AND_RESEARCH_REVIEW_2026-10-16.md#6-七个模块的研究汇报)；研究演变按需查历史，不从旧“下一项”选择任务。

## 继续开展研究：确认当前证据与停止点

**主线计划确定要回答的问题、方法和交付标准；STATUS定位已有证据、准确停止点和当前下一行动。** 下面是研究者或AI开始实质工作前的接续流程，不能用首次阅读路线代替。决策保存授权和方法变化，历史记录不决定当前任务。

1. 读[当前状态](STATUS.md)：先确认当前主问题和判断层次，再定位最后实质成果、本轮是否仅维护、准确停止点、关键缺口、可复用证据、资料／预算和留出边界。
2. 读[项目章程](PROJECT_CHARTER.md)：理解四阶段目标、未知模拟传输、真实可见信息和在线／离线边界。
3. 读STATUS引用的最新[决策](DECISIONS.md)及[有效主线计划](RESEARCH_PLAN_STATIC_FIXED_POINT_DIAGNOSTICS_2026-10-10.md)：D-140将学习信息→参数调整→实际位置／持续变化→码误差→改善空间整体贯通；误差机制与信息／校正能力继续为核心，其他研究服务关键缺口。用主线判断“为什么做、什么结果有意义”，用STATUS定位“已有证据、从哪里接续”。原机制方法及研究边界保持。
4. 读[Gu算法综合评价](reports/GU_ALGORITHM_EVALUATION_V1.md)：区分原文收益、本项目候选、已完成有限验收与开放问题；需要解释演变再读[综合分析](reports/RESEARCH_SYNTHESIS_2026-10-10.md)。
5. 按当前问题进入[理论索引](theory/README.md)和[结论—证据表](theory/STAGE2_CLAIM_EVIDENCE_LEDGER_V1.md)，或[实验报告索引](reports/experiments/README.md)。先读摘要、条件和局限，再读证明、代码与原数据。
6. 推导／运行前读[本地研究流程](../CONTRIBUTING.md#主线检查与细节停止)。先简要说明阶段主问题、已有关键证据、主要未决关系、本轮判别目标及结果如何改变主线判断，再按需要读规格／协议／源码。扩大细节前核对必要性和终点，收尾交付主线判断并更新状态／证据。

用户新指令优先。已批准范围内日常推导／核查／必要实现及具体协议冻结自主继续，不重复请求方向确认。新会话不机械追赶最近脚本的剩余小项；关键关系已支持、被否定或缺失条件已明确时先回主问题，不以极小未认证、更多覆盖或编号数量作为继续理由。计划批准不表示实验完成；不重跑已验收矩阵，不默认补第四窗／一般长期根，不把已消费Gu确认用作未来算法确认。新增长期验证先有主问题预测、用途和预算。

## 目录与文件职责

`docs/`根目录保留六份公共入口与约定：本指南、STATUS、章程、决策、唯一有效主线和写作约定。其余文档按下表归类。

| 位置 | 内容与维护方式 |
|---|---|
| `AGENTS.md`、根README | 自动阅读／项目总览入口，链接本指南；不再维护第二套规则或当前状态 |
| `docs/STATUS.md` | 唯一当前快照：当前主线问题、最后实质成果／本轮工作性质、关键支持／缺口、准确停止点、可复用证据、下一行动的必要性及边界 |
| `docs/DECISIONS.md` | 授权、范围、方法和验收标准变化的历史记录；日常推导不逐次造决策 |
| [有效主线计划](RESEARCH_PLAN_STATIC_FIXED_POINT_DIAGNOSTICS_2026-10-10.md) | 当前阶段只维护这一份有效方法；旧版本、旧计划与主线复核归入`docs/reports/`并显式标为历史；变更整合相关章节，不逐轮尾部补待办 |
| `docs/theory/` | 按问题组织定义、推导、条件结论、反例和开放证明；README定位文件，原证据表登记NG及证据层级 |
| `docs/reports/` | Gu集中评价、阶段综合分析、审查、汇报，以及历史计划、主线复核和状态归档；不复制全部实验表或推导 |
| `docs/reports/experiments/` | 经审查实验结果、条件、失败与局限；README按编号定位定义、报告和运行，不维护进展日志 |
| `docs/stages/`、`docs/specifications/` | 阶段资料导航／边界；架构、码制、测量和接口规格；原文来源与假设分开 |
| `docs/literature/` | [按主题定位已有文献与来源讨论](literature/README.md)；有实际阅读笔记时再增加文件，不预留空阶段分支 |
| `experiments/` | 每项实验专用README、协议／配置、运行与核对入口；同一实验的只读补分析可复用原目录 |
| `src/adc_research/` | 正式可复用模块；平台、理论、在线校准、离线评分与指标的信息边界保持 |
| `configs/`、`references/`、`tests/`、`rtl/`、`simulink_adc/` | 共享配置、来源、正式测试、硬件候选和独立行为模型；沿用各自README与发现入口 |
| `artifacts/runs/<实验>/<运行>/` | 原始数据、日志、图与核对；失败／预检／正式分开，原记录不覆盖 |
| `artifacts/research/`、`tmp/` | 本地只读分析、来源提取、维护备份和临时工作；正式证明／结论归入理论或报告，不以本地日志代替成果 |
| `legacy/`、旧TeX／PDF、`output/` | 历史原型、条件性底稿和导出制品；不当作现行一般理论或物理证明 |

不新增并列AI指南、工作流、成果清单、任务卡或每轮计划。新增文件须有独立问题或实现职责；不为命名统一搬动冻结实验、原数据或测试。NG编号是理论结果，EXP编号是实验对象，二者均不衡量整个阶段完成程度。

探索性笔记本有实际需要时再建目录；经验证的模型和算法归入`src/adc_research/`，正式结论归入理论或报告，不能只保存在笔记本中。测试继续使用现有根层发现方式，不预留无测试的分层目录。

## 复用、验证与会话收尾

- 确认模型、输入、后端、码制、步长、实际观测、状态／更新时间和预算。数学、程序一致、有限统计、物理适用性及工艺证据分别判断；同学习量与同转换时长分开。
- 理想输入、模拟传输、目标码、oracle和离线参照不进入在线算法。额外历史／shadow读出须说明信息与成本；较优离线参照不证明在线可达到。
- 本地文献和运行数据默认Git忽略。先检查资料可得性；缺失就登记不可复算范围，不用合成替代品冒充原数据，不自动重跑大实验。
- 链接按文件所在位置解析，命令从仓库根运行；旧机器绝对路径不当本机路径。索引检查须涵盖链接、理论／实验覆盖和历史状态标签。
- 收尾先同步原理论／报告与证据表，再整体更新STATUS；旧快照归入既有历史。维护轮与实质研究轮分开，未完成证明／预检／实验和明确停止点写清。
- 修订方法时整体整合主线并保留旧计划／状态原文；理论和阶段README只定位资料，不追加详细轮次进展或自己的“下一项”。提交／推送依用户授权。

术语和写作见[统一约定](TECHNICAL_WRITING_CONVENTIONS_V1.md)。历史语言审查见[审查记录](reports/DOCUMENT_LANGUAGE_AUDIT_V1.md)；当前方法和进度始终分别由主线计划与STATUS维护。
