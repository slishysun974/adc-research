# EXP-021：Gu 候选算法在未见过的模拟曲线上的冷启动

本实验接续 EXP-020 的信息边界检查，研究一个不同的问题：在线算法不知道模拟传输的形状时，使用同一套数字 PWL 分段、步长和训练安排，能否在不同模拟曲线上从单位系数开始改善最终 ADC 输出？

## 冻结的协议

- 架构取 `gu_behavioral_v1`，数字校正和 gated-LMS 更新只接收两级符号码、末级中心码、两级 dither 标记。在线分段宽度由架构位宽推出，不从任何模拟曲线或 oracle 取得。
- 沿用 EXP-010 的四个归一化步长 `0.001/0.003/0.006/0.012`、系数范围 `[0,2]`。每条曲线都从全 1 系数冷启动，训练 64 轮；每轮包含所有 4096 个输入码中心和四种 dither 组合，轮内用同一随机种子打乱。没有用另一条曲线训练出的系数热启动。
- 历史合成模拟 PWL 为对照。两条预先指定的三次多项式曲线为新测试条件；它们是连续、严格单调的**模拟测试模型**，其形状与数字 PWL 校正的分段无关。均未声称对应实际芯片。
- 独立随机输入先用于记录各训练检查点的平均码误差；它不决定步长或停止轮次。另一个随机输入种子和 8192 点相干正弦只在 64 轮后评分。正弦的 dither 符号由固定种子生成，两个模拟曲线使用同一符号序列。
- 同时报告未学习的单位系数和训练后系数：留出随机输入的平均码误差、数字饱和和物理过载；留出正弦的 SNDR/SFDR；以及每个分段的系数和有效更新次数。协议通过只要求数据流和物理有效性，不预设算法必须改善。

运行：

```powershell
$env:PYTHONPATH='src'
python experiments/exp_021_gu_cross_curve_cold_start/run.py --run-id <unique-run-id>
```

结果写入 `artifacts/runs/EXP_021/<run-id>/summary.json`。阶段结论见[实验报告](../../docs/reports/experiments/EXP_021_GU_CROSS_CURVE_COLD_START_V1.md)。

对压缩曲线的事后诊断可运行 `python experiments/exp_021_gu_cross_curve_cold_start/diagnose.py --run-id <run-id>`。它在验证输入上替换第 32/64 轮的单个系数，并在训练码中心上求第一级第一段的平均去相关量；不使用最终留出选择参数。输出另存为 `validation_diagnostic_v6.json`。

## 适用范围

这是静态、浮点的 Gu 候选实现；第一辅路仍是主路的仿射副本。训练多轮重复同一组码中心，与实际电路的连续后台流和真实 dither 时序不同。64 轮终点也不自动等于稳态。模型没有热噪声、时钟抖动、PVT 漂移或定点/RTL 限制；频谱数值只属于所列合成条件。
